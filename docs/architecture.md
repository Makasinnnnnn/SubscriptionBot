# Платежи и доступ

Счёт и подписка — разные сущности. Подтверждённый платёж ещё не означает, что внешняя система выдала доступ.

API проверяет провайдера, идентификатор счёта, сумму и валюту. Crypto Pay дополнительно проверяется по подписи и времени события, ЮKassa — запросом статуса через API. Повторное уведомление не должно повторно продлевать подписку.

При сбое выдачи приглашений используются savepoint и компенсационный отзыв уже созданной ссылки. Оплаченный счёт без подписки можно повторно обработать через администратора. Полной распределённой транзакции между БД и Telegram здесь нет.

## Данные и права

Основные сущности: User, Channel, Plan, Payment, Subscription, InviteLink, PromoCode и WebhookEvent. Схема хранится в `app/db/models/`, изменения — в `alembic/versions/`.

Superadmin управляет администраторами и глобальными настройками. Admin работает в пределах разрешённых каналов. Support имеет доступ на чтение. Изменения записываются в AuditLog.

Через `/admin` доступны каналы, тарифы, доступы, платежи, промокоды, поддержка и интервалы напоминаний. Архивирование тарифа не удаляет историю. Технический бот запускается отдельным сервисом ops.

## Проверка перед использованием

Это сценарии для проверки, а не отчёт о проведённых испытаниях реальных интеграций.

- Оплата, повторное событие и продление не создают лишний доступ.
- Сбой второй ссылки оставляет платёж доступным для повторной обработки.
- Возврат, ручной отзыв и истечение срока удаляют доступ в обоих каналах.
- Права администратора действуют и на отчёты, и на изменения.
- Промокод учитывается только после успешной выдачи доступа.
- Проверены реальные интеграции каждого включённого провайдера и восстановление в отдельной БД.

Юридические тексты из `legal/` читает бот: это рабочие файлы, а не лишняя документация. Перед реальным использованием их необходимо проверить для конкретного продукта. При существенном изменении повышается LEGAL_VERSION.

Дальнейшие задачи: постоянная очередь повторов, общий rate limit при нескольких экземплярах API, метрики конверсии и оттока. Не считать сохранённый старый результат тестов подтверждением текущей версии.
